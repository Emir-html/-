# Функция сохранения прогресса — контракт и проверка

## Где что
- `state/progress-merge.js` — правила слияния (чистые функции, без записи в хранилище).
- `tools/apply_progress_patch.py` — встраивает их в `BackupPanel` приложения.
- `test/progress-merge.test.mjs` — 20 проверок.

## Контракт
**Выгрузка** → файл `progress.json`:
```json
{ "app": "mirstudy", "version": 2, "exportedAt": "ISO-дата",
  "summary": { "economics": {...}, "social": {...}, "finlit": {"studied": [...], "struggling": 3, "tests": "80% из 40"},
               "business": {...}, "russian": {...}, "hoursTotal": 52.4 },
  "data": { "<ключ хранилища>": <значение как объект> } }
```
Берутся все ключи хранилища (`window.storage.list`), статический список — запасной путь.

**Загрузка** — принимает v1 (старые файлы) и v2. Для каждого ключа:
`итог = mergeValue(ключ, локальное, из_файла)`; записываются только изменившиеся ключи,
затем страница перезагружается (иначе компоненты перезапишут данные старым состоянием из памяти).

| Данные | Правило |
|---|---|
| SM-2 (`review-state`, `social-review-state`) | по каждой карточке — более новая по `last` |
| задачи, трудные карточки/вопросы | по каждой записи — более новая по `at` |
| `*-checked`, `*-reviewed` | OR: изучено, если отмечено хоть где-то |
| счётчики тестов, `topic-progress`, статистика тем | максимум по каждому полю (не сумма!) |
| серии | более поздняя `lastDate` |
| свои карточки | объединение по `id` |
| `q1-history` (пробные экзамены) | объединение по времени попытки, новые сверху, ≤60 |
| `time-v2` | максимум по каждому дню и общему итогу |
| `ui-theme` | всегда локальная |
| неизвестный новый ключ | числа — max, флаги — OR, массивы — объединение без дублей, прочее — локальное |

## Гарантии
1. Идемпотентность — повторный импорт того же файла: «Всё уже совпадает».
2. Ничего локального не теряется.
3. Порядок устройств не влияет на результат.

## Осознанные компромиссы
- Снятую отметку «изучено» импорт старого файла вернёт (OR). Цена надёжности: без
  меток времени у флагов иначе нельзя отличить «сняли» от «ещё не ставили».
- Карточка, убранная из «трудных» на одном устройстве, может вернуться с другого —
  безвредно: лишний раз попадёт в повторение.
- Время занятий с двух устройств не суммируется, а берётся максимум за день —
  иначе повторный импорт удваивал бы часы. Точная сумма — задача облачной синхронизации.

## Как проверить перед встраиванием
1. `node test/progress-merge.test.mjs` → «Все 20 проверок пройдены».
2. `python3 tools/apply_progress_patch.py app/econ-trainer.jsx` дважды — второй прогон
   не меняет файл; затем esbuild без ошибок.
3. Вручную в артефакте: «Выгрузить» → открыть progress.json, проверить `summary`;
   «Загрузить» тот же файл → должно быть «Всё уже совпадает — ничего не изменено».
