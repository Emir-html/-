# MirStudy × Claude: как строить игру максимально эффективно

1 октября 2026

## Коротко

Твой порядок «концепция → цифры → анимация → дизайн» верный, с одной поправкой: грубую раскладку экранов (вайрфрейм) нужно зафиксировать до анимации, а визуальный стиль — в конце. Иначе анимации придётся переделывать под новую вёрстку.

Главный совет: разработку игры перенеси в Claude Code на своём компьютере, а этот чат оставь для экономики, концепции и баланса. Сейчас мы правим файл на 48 000 строк (6 МБ) через копирование в контейнер и Python-замены — для контента это работает, для игры с анимациями это слишком хрупко и медленно.

| Что делаем | Где | Модель |
| --- | --- | --- |
| Концепция, экономическая модель, формулы, баланс | Чат Claude (этот проект) + выполнение кода | Opus 5.5 |
| Код игры, тесты, анимация, рефакторинг | Claude Code (вкладка Code в Claude Desktop) | Sonnet 5.5, сложное — Opus 5.5 |
| Поиск визуального стиля, макеты экранов | Claude Design (claude.ai/design) | встроенная |
| Перенос макета в код | Claude Design → передача в Claude Code | Sonnet 5.5 |

GitHub для локальной игры не обязателен: хватит локального git внутри Claude Code. Cowork для этого проекта не нужен.

## Карта инструментов

| Инструмент | Сильная сторона | Слабое место для игры | Когда брать |
| --- | --- | --- | --- |
| Чат Claude (этот проект) | Рассуждения, формулы, симуляции, документы, память проекта, коннекторы | Файлы во временном контейнере; нет запуска приложения в браузере | Концепция, экономика, баланс, контент уроков |
| Claude Code | Работает с папкой на диске, запускает команды, тесты и dev-сервер, ведёт git, CLAUDE.md, навыки, субагенты, хуки | Нужна установка; без чёткой задачи может «расползтись» по коду | Весь код игры и приложения |
| Claude Design | Холст с живым интерактивным макетом, правки по клику, панель Tweaks, передача пакета в Claude Code | Research preview; это не движок игры | Поиск стиля, макеты, дизайн-система |
| Cowork | Агент для офисной работы с файлами | Для разработки избыточен | Можно пропустить |

CLAUDE.md — правила, которые Claude Code видит в каждой сессии (короче 200 строк). Навыки — инструкции и скрипты по требованию или командой `/имя`. Субагенты — помощники со своим контекстом. Хуки — автоматические действия, например сборка после каждой правки. MCP — доступ к внешним системам.

## Этапы развития

Твой план я бы оставил, но добавил один этап: серый прототип между цифрами и анимацией.

1. **Концепция** — чат Claude, Opus 5.5. Основной цикл, цели игрока, экономические темы, список механик и того, чего точно не будет.
   *Ворота:* дизайн-документ на одну страницу.
2. **Модель в цифрах** — Claude Code, model.js без экранов. Формулы, симулятор, тесты, боты-стратегии; таблицы прибыли, кривая прогресса.
   *Ворота:* оптимальная стратегия выигрывает, тупая — нет; тесты зелёные.
3. **Серый прототип** (новый этап) — раскладка экранов на серых блоках, телефон 380 px; 20 минут своей игры.
   *Ворота:* после 20 минут хочется сыграть ещё один день.
4. **Анимация** — Claude Code, Sonnet 5.5. Отклик на каждое действие до 300 мс, prefers-reduced-motion, логика не меняется.
   *Ворота:* каждое решение игрока видно на экране.
5. **Дизайн** — Claude Design → Claude Code. 2–3 направления стиля, выбор, дизайн-система, применение ко всем экранам.
   *Готово:* дизайн-система применена везде, баланс проверен заново.

Ошибку в балансе дешевле всего найти на этапе 2, когда интерфейса ещё нет.

## Что подключить

| Что | Нужно? | Зачем |
| --- | --- | --- |
| Claude Code + локальный git | Да, сразу | Откат любой правки, история изменений |
| CLAUDE.md | Да, сразу | Наши правила: не трогать изученный контент, COLORS, `globalThis.Map`, сборка, слияние прогресса |
| Vite + заглушка `window.storage` | Да | Приложение открывается в браузере на localhost |
| Навык `lavka-balance` | Да | Одна команда — симуляция трёх стратегий и таблица прибыли |
| Навык или субагент «экономист» | Да | Проверка формул и теории перед коммитом |
| Хук после правки | Желательно | Автосборка esbuild и тесты |
| GitHub | Пока нет | Позже — резервная копия и деплой на VPS |
| Figma, Canva | Нет | Claude Design удобнее |

## Модели и лимиты

| Модель | Для чего |
| --- | --- |
| Opus 5.5 | Концепция, модель, архитектура, трудные баги, ревью баланса |
| Sonnet 5.5 | Основная работа в Claude Code |
| Haiku 4.5 | Рутина |
| Fable 5.1 | Если есть в тарифе — точечно, для большого рефакторинга или финального ревью |

Одна задача — одна сессия; сначала план, потом код; длинные сессии перезапускать с короткой сводкой.

## Шаблоны запросов

1. **Концепция.** «Опиши механику X: что решает игрок, какую идею открывает сам, формулы, как это ломает баланс. Без кода».
2. **Модель.** «Добавь в model.js механику X. Сначала тесты, потом код. Прогони /lavka-balance».
3. **Интерфейс.** «Экран X на серых блоках, всё влезает в 380 px».
4. **Анимация.** «Анимация X до 300 мс, reduced motion, логику не трогай».
5. **Ревью.** «Сыграй за новичка 10 дней по логам. Где скучно, где тупая стратегия выигрывает?»
