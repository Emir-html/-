# «Лавка» — спецификация текущей версии

Снимок на 1 октября 2026 (econ-trainer__17_.jsx), обновлён после исправлений по ревью экономиста (модель v2). Код: `src/games/lavka/model.js` (логика), `src/games/lavka/ui.jsx` (экраны). Это описание того, что уже работает, а не дизайн-документ будущей игры.

## Суть

Уютный тайкун в разделе «Перерыв» главного экрана MirStudy. Каждое утро игрок ставит цену и закупку по каждому товару, затем смотрит анимированный день (8:00–20:00) и вечерний отчёт. Цель игрока — прибыль; цель приложения — чтобы игрок сам нащупал MR = MC и связанные идеи олимпиадной микроэкономики.

## Главы (кривая сложности)

| Глава | С какого дня | События | Улучшения | Ключевая цель для следующей |
| --- | --- | --- | --- | --- |
| 1. Спрос | 1 | жара, ливень, фестиваль | тетрадь, холодильник, помощник | «Чуйка монополиста» |
| 2. Издержки и налоги | 8 | мука, акциз, блогер | вывеска, оптовик, кофемашина | «Неделя в плюсе» |
| 3. Регулирование и рынки | 15 | потолок цен, Семён | морозильник, вторая точка | — (дальше экзамен) |

Глава открывается, когда наступил её день **и** выполнена цель прошлой. Купленное раньше не отнимается;
старое сохранение без поля `chapter` получает главу по номеру дня.

**Вердикт отчёта:** дни 1–7 — «оракул» (истинные A, B, λ); дальше — по тетради (MR = 2P − α/β, |E|, CS, DWL — оценки;
только в обычный день — см. «Тетрадь в дни событий» ниже — и при ≥ 3 обычных наблюдениях); иначе — только факты (продано, дефицит, очередь, порча).
Цели всегда судят по истинным значениям.

## Модель рынка

| Величина | Формула / значение |
| --- | --- |
| Спрос точки на товар | Q = k·(a·aMult − b·bMult·P) = A − B·P: A = a · aMult · k · события, B = b · bMult · k · события |
| k (число покупателей) | день недели × лояльность × вывеска 1,15 × фестиваль 1,3 — растут и A, и B, P* не меняется |
| Шум | реализованный спрос = round(E[Q] · U[0,92; 1,08]) |
| MC | закупка c (×0,85 с оптовиком) + акциз |
| Оптимум товара | P* = (A/B + MC)/2; при потолке между MC и P* — P* = потолок |
| Оптимум точки (мощность) | MRᵢ = MCᵢ + λ, ΣQᵢ ≤ мощность; Pᵢ = (Aᵢ/Bᵢ + MCᵢ + λ)/2, λ ≥ 0 — теневая цена места (`lavkaPlan`) |
| MR при цене P | 2P − A/B |
| Эластичность | B·P/Q |
| Мощность | 120 покупателей/день на точку (+100 с помощником); при перегрузке продажи режутся пропорционально |
| Порча | всё непроданное выбрасывается; с холодильником 80% переходит на завтра |
| CS | S·(A/B − P) − S²/(2B) |
| DWL | TS(Q_эфф) − TS(S), TS(S) = S·(A/B − c) − S²/(2B), Q_эфф = A − B·c |

### Лояльность

Диапазон 80–110%, множитель к спросу. Если без товара ушли ≤ 3% желающих — +2 п.п., иначе −0,3 × доля ушедших. Делает дефицит скрытыми издержками (задача газетчика).

| Блогер | круассан A ×1,3, B ×0,75 | правило Лернера |

| Конкурент «Семён» | 4 дня, товар у парка: Q = 0,55A − BP + 0,5B·Pк; Pк = наилучший ответ на вчерашнюю цену игрока | Бертран с дифф. товаром, сходимость к Нэшу |

## Прочее

- Старт: 2 000 ₽, день 1 = понедельник. Кредит 3 000 ₽ → долг 3 300 ₽, гасится половиной прибыли, доступен при кассе < 1 500 ₽ (до двух кредитов).
- Цели с наградами: первая прибыль (300), точная закупка (800), чуйка монополиста |MR − (MC + λ)| ≤ 3 без дефицита (1 500), парадокс потолка (2 000), пережил Семёна (2 000), дискриминация III степени (3 000), любимая лавка 105% (1 500), неделя в плюсе (2 500), 10 верных ответов (2 000), капитал 50 000, 30 дней.
- «Вопрос дня»: 15 задач в духе ВП, +400 ₽ за верный ответ, порядок вариантов перемешивается по дню.
- Отчёт дня: выручка, закупка, акциз, постоянные издержки, по товару — цена, спрос, продано, дефицит, очередь, порча, |E|, CS, излишек продавца, DWL, вердикт `lavkaVerdict` (MR vs MC + λ; потолок; дефицит → закупка; очередь → мощность); лояльность; итоги недели; прогноз на завтра.
- Сохранение: ключ `lavka-save` в `window.storage`, правило слияния `newer` (по полю `at`), ключ в `BACKUP_KEYS`. Поле `model` (сейчас 2): при загрузке старого сохранения (`lavkaLoad`) наблюдения старой модели исключаются из тетради.
- Управление: Enter — открыть лавку / следующее утро.

**Тетрадь в дни событий:** акциз, мука, потолок и фестиваль не меняют кривую одного покупателя — эти дни остаются «обычными»
(наблюдения идут в МНК, вердикт по тетради с новым MC). Жара, ливень, блогер и Семён — дни событий.
До исправлений (модель v1): оптимум ≈ 367 000, закупка 85% ≈ 180 000, дорого ≈ 157 000, 50 ₽ ≈ 74 000, дёшево ≈ −50 000.

## Известные слабые места (кандидаты для этапов 2–3)

- Поздняя игра разгоняется слишком быстро: при оптимальной игре касса > 300 000 к 40-му дню, а целей и трат после второй точки нет.
- Вердикт MR vs MC в отчёте опирается на истинные параметры — «подсказка оракула». Решено и сделано: только первая неделя, дальше — по тетради или только факты.
- Мощность теперь в оптимуме (λ), но лояльность по-прежнему падает и от очереди, и от дефицита одинаково.
- Кривая сложности есть (главы), но закупка 85% навсегда остаётся в главе 1: подсказка в «Целях» объясняет, что нужно; стоит проверить на живой игре.
- В Вопросе дня 15 задач — по кругу через 15 дней.
