# Сводка для чата Claude (проект MirStudy): уровни «Лавки»

Скопируй всё ниже в чат.

---

Обсуждаем концепцию игры «Лавка» в MirStudy (этап 1, Opus). Уже решено:
- «Лавка» — главный тренажёр олимпиадной микроэкономики («Высшая проба»), вход в разделе «Перерыв».
- Вердикт MR vs MC по истинным параметрам («оракул») — только в первую неделю уровня, дальше — по тетради игрока.
- «Вопрос дня» — из карточек и тестов уроков MirStudy по темам текущего уровня, слабые по SM-2 — чаще.
- Прогрессия «Путь компании» принята как основа:
  1. Лавка (монополия: спрос, MR = MC, издержки, налог, потолок) — уже есть;
  2. Ярмарка (Бертран, Курно, вход фирм, P → MC);
  3. Сеть кофеен (несколько рынков, мощность и теневая цена, эффект масштаба);
  4. Своё производство (найм MRP = w, make-or-buy, двойная маржинализация);
  5. Холдинг (NPV, кредит, налоги, риск).
  Переход — экзамен: 3 дня без подсказок с незнакомым шоком; эффективность = прибыль игрока / прибыль бота-оптимизатора
  на тех же случайных событиях; медали 70/85/95%. Капитал: «продать» (цена = дивиденд / r) или «оставить дочкой»
  (дивиденд = средняя прибыль × эффективность); минимальный стартовый грант на каждом уровне.

Известные проблемы текущей модели (ревью экономиста, 70%): мощность 120 ограничивает почти всегда, а оптимум её
не учитывает; «больше покупателей» смоделировано как рост A без роста B; МНК в тетради искажает наклон; вердикт при
потолке и при дефиците даёт неверный совет.

Вопросы к обсуждению:
1. Для уровней 2–5: какие решения принимает игрок каждый день, какая модель (формулы, параметры), какую идею он
   «открывает сам», какие 3 ключевые цели и какой шок на экзамене?
2. Ставка r для «продать vs оставить дочкой»: какое значение, чтобы выбор был неочевидным для среднего игрока?
3. Мощность на уровне 1: учить теневую цену λ уже здесь (MR = MC + λ) или поднять мощность и отложить до уровня 3?
4. «Больше покупателей» (фестиваль, выходные): Q = k·(A − B·P) (P* не меняется — урок) или «те же люди платят больше»?
5. Как бот-оптимизатор считает «идеальную» прибыль, если оптимум с мощностью и лояльностью динамический?

Итог нужен в виде одностраничных дополнений к docs/GAME_DESIGN.md по каждому уровню.
